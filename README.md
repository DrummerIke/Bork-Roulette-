# Bork Roulette

Встраиваемый виджет без внешнего CDN для Google Sites с прозрачным фоном: форма сохраняет телефон сотрудника на выбранную дату, рандомайзер по паролю выбирает случайный сохраненный номер за выбранный день, сохраняет чек-лист прослушивания, а статистика по тому же паролю показывает, кто из сотрудников заполнил форму за день и какие результаты отборов сохранены.

## Настройка Supabase

> **Обязательно после этого обновления:** откройте Supabase → SQL Editor, вставьте весь актуальный `supabase.sql`, нажмите **Run**, дождитесь `Success`, затем перезагрузите страницу Google Sites. Ошибка `Could not find the function public.get_roulette_employees` означает, что этот SQL ещё не был выполнен в используемом Supabase-проекте.

1. Выполните SQL из `supabase.sql` в Supabase SQL Editor.
2. Убедитесь, что таблица `public.employees` содержит поля `id uuid`, `name text` и `Position text`. Также поддерживается переименованный столбец `position` или `role`; для участия в форме и отборе его значение должно быть `Personal Consultant` (регистр и случайные пробелы виджет нормализует).
3. Для статистики по умолчанию используется `public.office_shifts`. Помимо обычных дат/JSON поддерживается фактическая матрица этой таблицы: `col1` — ФИО, `col2` — понедельник, …, `col6` — пятница. Пустые значения, `—`, `0`, «В/Вых», «О», «Б» считаются нерабочими. Если график хранится в другой таблице, задайте её имя через `window.BORK_OFFICE_SHIFTS_TABLE` перед загрузкой `src/app.js`.
4. Виджет уже содержит текущий публичный Supabase URL как fallback. Если ключ нужно заменить, в Google Sites перед `src/app.js` задайте публичные ключи проекта:

```html
<script>
  window.BORK_SUPABASE_URL = 'https://mhtbolnovisgdliphsmf.supabase.co';
  window.BORK_SUPABASE_ANON_KEY = 'your-anon-key';
</script>
```

Supabase REST API уже отдает CORS-заголовки для браузерных клиентов. Для встраивания оставлен прозрачный фон `html/body`, чтобы виджет наследовал фон Google Sites. Доступ к вкладкам рандомайзера и статистики закрыт клиентским паролем `06062025`.

Если после создания других таблиц перестали загружаться сотрудники или результаты, повторно выполните актуальный `supabase.sql`: он не удаляет данные, восстанавливает `GRANT`/RLS-доступ, создаёт резервную функцию `get_roulette_employees()` и перезагружает schema cache PostgREST. При ошибке `permission denied for table employees` виджет автоматически переключается с прямого чтения таблицы на эту функцию. Виджет также не использует вложенные REST-связи `employees(...)`, поэтому новые внешние ключи не могут сделать запрос неоднозначным.

В статистике список «Не заполнили» строится только по сотрудникам, найденным в графике на выбранную дату. Если график недоступен, список намеренно скрывается: так выходной сотрудник не будет ошибочно отмечен как не заполнивший.

Сначала статистика вызывает RPC `get_roulette_working_employees`. Если функция отсутствует в schema cache или временно недоступна, приложение автоматически читает строки выбранной даты непосредственно из `office_shifts`. Актуальный SQL предоставляет `anon` только чтение этой таблицы.

## Локальная проверка

```bash
npm test
```

Виджет использует локальный REST-клиент `src/supabase-client.js`, поэтому ему не нужен `esm.sh`/другой CDN для подключения к Supabase.
